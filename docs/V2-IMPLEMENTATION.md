## v2.2 修改记录（依据《v2.2修改.md》10 条反馈）

1. **性取向“其他”自由填写**：`Orientation` 新增 `other`；`V2Profile.orientationCustom`（≤12 字，仅选“其他”时可填，非“其他”时服务端拒绝并自动清空）；展示统一走 `orientationDisplay()`（我的/了解页均显示“其他：xxx”）。
2. **文案**：“+ 添加一栏联系方式”→“+ 添加联系方式”。
3. **头像自定义**：新增 `src/lib/domain/avatars.ts`（6 个官方头像：铃铛/晚樱/咖啡/奶猫/星月/音符，品牌色 SVG 插画）与统一 `Avatar` 组件（`def:` 官方 / `data:image` 上传 / 历史表情三形态）；编辑资料含头像九宫格 + 上传（前端 canvas 压缩 256×256 JPEG，服务端校验 MIME 与 ≤300k 字符）。头像出现在顶栏按钮、我的、了解页。
4. **年龄窗口→出生年代**：`ageCohorts`（70后—05后）下拉选择；服务端拒绝旧格式区间；展示标签改“出生年代”。
5. **邮箱验证去掉**：fixtures 的 `verificationLevels` 移除“邮箱已验证”。
6. **雷达倒计时修复**：根因——前端 `remaining = expiresAt − virtualNow − tick×1s`，而 shell 每 1.2s 轮询已刷新 `virtualNow`，双重计时导致 10 分钟约 5 分钟走完、重进页面 tick 归零时间“跳回”。修复：以“到期时间 − (virtualNow + 距上次同步的真实毫秒)”计算，每秒仅触发重绘；倒计时显示精确到秒。服务端 `setRadar`：雷达已开启时重复调用只更新特征、**不重置 expiresAt**（关闭/到期后重开才新一轮）。浏览器实测 3.2s 实际时间恰好递减 3 秒。
7. **日记写入修复**：根因——`DiaryEditor` 重置 effect 依赖 `[open, virtualNow]`，轮询每 1.2s 刷新 `virtualNow` → 表单（标题/正文/图片/草稿勾选）被周期清空；`MeDrawer` 的 `[editOpen, view]` 同理。修复：虚拟时钟经 ref 读取、仅在弹层打开瞬间初始化一次。浏览器实测输入 3.6s（3 轮轮询）后内容完好并成功保存。
8. **承诺存证（上链）**：`confirmPromise` 双方确认生效 → `enqueueAnchor("promise", v1)`（条款：内容/验收/截止/责任人/计分/双方确认时间）；`maybeAnchorPromiseSettlement` 在全部责任人结算（fulfilled 需对方确认证据、unfulfilled 本人确认即成立、waived 双方豁免）后锚定 v2（结果+证据+确认人），争议复核（演示台）后锚定 v3 并链上 `previousVersionCommitment` 指向 v2；`PromiseDoc.anchor/previousVersionCommitment` 落位，时间线与承诺弹层展示存证状态与“查看证据”。
9. **履约提示修复**：`resolutionStatusText` 原先只要任一责任项有证据就显示“待确认履约证据”（确认完仍残留）。改为：仅当存在“pending 且已提交证据”的责任项才提示；部分结算显示“部分已完成”、全部完成“已完成”、含未完成“已结算（含未完成）”；承诺弹层印章跟随进度（已完成/已结算/承诺生效/待确认）。
10. **空间设置**：`V2Relationship.spaceSettings`（name/theme/showDays，建关系时初始化默认值）+ `POST /space-settings`（成员可改，双方同步）；UI 独立“空间设置”弹层（名称输入、5 款主题色板、天数显示开关），hero 按主题着色（theme-sakura/mint/amber/moon CSS）。**需求确认**：可自定义=名称/主题/天数展示（未来候选：封面、纪念日清单、情侣问答）；不可自定义=计分规则/存证条款/对方资料/已确认历史（公平与合规）。

## 二、四阶段实现状态

### 1. 相遇（保留原机制 + 新增门槛）

- 10 分钟雷达、临时特征（2–3 项）、匿名摇铃（三句预设、同轮次一次）、回响后双方揭晓：保留并迁入 V2 服务（`services/meet.ts`）。
- 未回响前 API 响应不含对方档案；铃声匿名（from 不泄露）；雷达仅显示临时特征与演示街区。
- 联系方式交换独立授权（`share-grants scope=profile_contact`，72h，可撤销；拒绝不影响继续了解）。
- **MEET-06**：已有 active/married 关系时，服务端拦截开启雷达与摇铃（403），UI 显示"你们的故事正在继续"。
- 连接关闭（MEET-07）：停止新铃声与互访，保留本人记录。

### 2. 了解（履约参考）

- 页面顺序：意向（认真恋爱/先认识再决定/暂不寻求稳定关系）→ 应用内状态 → 获授权的履约摘要。
- **计分公式（score.ts，严格按计划书 4.3）**：`score = round(100×(s+1)/(n+2))`；n<3、coverage<0.8、存在未决申诉 → null。明细展示 s/f/pending/coverage/asOf/algorithmVersion/来源。
- 数据源锁定**最近一段已结束关系**（endedAt 降序），不回退更早高分；当前进行中的关系不对外评分。
- 演示 fixtures：B 预置虚构前史（4 成功 1 失败 → **71 分**，卡片持续标注"演示数据"）；A 无历史（"暂无足够记录"，不显示 0 分）。
- 授权：摘要查看需 owner→audience 专项授权（72h、可撤销、每次读取校验版本与撤销状态）；撤销后显示"目前未开放参考记录"，不暗示失信。
- 结算/申诉变化 → 生成新摘要版本并撤销旧版本（`refreshTrustSnapshot`）。
- 不做：人品认证、约炮概率、前任名单、公开排行榜。

### 3. 我们（日记与承诺）

- 关系空间：共同封面、在一起天数、下一个纪念日倒计时、日记/承诺/纪念筛选、系统纪念节点（关系第一天）。
- 日记：私人草稿（仅作者可见）→ 发送 → 双方确认（绑定具体版本）→ 可存证；**修改生成新版本并使旧确认失效**（expectedVersion 乐观并发，冲突返回 VERSION_CONFLICT）；退回/撤回；标题 40 字、正文 3000 字、≤6 张演示图片（本地演示库，指纹确定性）。
- 承诺：责任人/截止/验收方式/是否计分；双方确认生效；计分项 ≥24h 提前、每关系 ≤10 项、每自然日 ≤1 项；限制人身自由类承诺被服务端拒绝；履约 = 责任人提交证据 + 对方确认（或本人确认未完成）；豁免需双方同意；申诉转人工复核并冻结分数。
- 关系结束：本人单方确认立即生效；待确认内容冻结；计划独立处理；归档仅本人可见只读。
- 业务确认与存证状态分离展示（三维度：业务/存证/来源）。

### 4. 相守（演示版完整状态流）

- 双方各投 100 演示点（初始 1000，系统发放、不可购买/转让/提现）→ 激活前原子检查（双方余额 + 奖励预留），无半激活状态 → 24h 冷静期（取消全额退款）→ 365 天有效 + 30 天宽限。
- 达成申请（目标须在冷静期后~到期前；去重）→ 演示台审核（通过/补材料/不通过；审核 7 天/补正 14 天期限，超期转例外复核）→ 7 天争议期 → 领取（幂等，重复点击不重复发放）。
- 奖励 A：各返 100 + 各 50 点（独立奖励预算，激活前预留 100 点）；奖励 B：各返 100 + 一张 99 朵玫瑰演示券（领取人预设，不可实际核销/转卖）。
- 普通结束 → 7 天异议窗口 → 投入共 200 点记入**不可流通的演示失效账户**（不转给任何人）+ 释放奖励预留。
- 例外复核：安全/系统例外冻结结算（30 天未完成按平台无法履约取消并退回本金）；审核中退出关系 → 关系立即结束、计划转复核、已成立权益不被销毁（T21 验证）。
- 退出关系不需要等待结算或对方同意；婚姻目标通过仅 active 关系转 married（已结束不自动复合）。
- 账本：`LedgerEntry` 正整数、businessKey 幂等唯一、余额不为负；点数账本与履约分完全独立。

## 四、技术架构

```
UI(Next.js 四栏) → /api/v2 统一入口 → session → services(meet/relationship/trust/
diary/plan/anchor/admin/view) → repositories/demo-repo(内存+fixtures)
                                  → chain/commitment(JCS+SHA256+salt)
                                  → registry(虚拟时钟+时间驱动清扫 sweep)
```

- 所有权限/状态迁移/并发（expectedVersion、revision、businessKey）在服务端校验。
- 状态清扫（sweep）：雷达/铃声/邀请过期、计划到期失效、异议窗口结束、争议期结束转可领取、审核超期转复核——时间驱动迁移与显式操作走同一套结算函数。
- 旧 `/api/demo`（V1）保留给 `verify:demo` 回归，live 模式禁写；旧合约与旧记录兼容只读，V2 不改写其含义。
- 新增 devDependencies：`@ethereumjs/{evm,common,util,tx,block}`（仅合约本地行为测试使用）。

## 八、已知边界

- viewer 是本地演示会话（正式环境必须换可信会话；集中在 session.ts 便于替换）。
- 同一浏览器扩展钱包可能共享账户；双人真实上链用不同浏览器。
- 虚拟时钟只推进业务时间，不用于验证真实证件条件，不修改链上时间。
