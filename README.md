# 心动铃铛 · Heartbell

**从一次心动，到共同写下的未来。**

Next.js + TypeScript 全链条恋爱产品演示：**相遇 → 了解 → 我们 → 相守** 四个阶段，A/B 双窗口独立演示（C 为安全验证第三人），内置关系状态机、履约分算法、日记版本确认、演示点数账本与 V2 承诺登记合约。默认 preview 模式无需数据库或钱包即可启动。

## v2.7 更新（依据《双用户实测-20261007》：A/B 双用户 + 后台实测修复）

1. **P0 权限修复**：他人无法再读取/改写私人草稿（详情 404 掩护 + 改版 403）；日记确认/退回/撤回必须携带 `expectedVersion`，旧版本请求返回 409——"看旧版却确认了新版"被杜绝；关系结束后共同写入全面冻结（只读归档，履约结算走独立流程）。
2. **后台工单闭环**：`/ops/session` 返回 `accountId`，页面按真实受理人判断——自己领取的工单可正常审核提交（此前被误判"他人受理"而卡死）。
3. **可用性修复**：附件分批添加不再误报"已满"；确认/退回后弹窗即时刷新并自动同步对方改版；「写下今天」固定在列表上方 + 时间线搜索/日期筛选/分页 + 待确认折叠；旧归档可点开只读查看与检索。
4. **数据可靠性**：日记/承诺创建支持 `Idempotency-Key` 服务端幂等（重试不产生重复）；日期统一业务时区（北京时间）并校验真实日历（拒绝 2026-02-30）；附件按解码字节 ≤600KB 与前端同口径，校验文件魔数（纯文本冒充 png 被拒）。
5. **邀请体验**：未绑定但收到邀请时，「我们」页直接显示"回应邀请"卡片（含邀请人），不再误导去发起新邀请。

验证：`npm run verify:v27`（33 项新增专项，逐条复现实测缺陷）+ `verify:v2`（104 项）+ `verify:v25`（68 项）+ `verify:safety`（76 项）+ `tsc` + 生产构建全部通过。明细见 [CHANGELOG.md](CHANGELOG.md)。

## v2.6 更新（依据《v2.6修改.md》：v2.5 登录交付 + v2.2 安全与隐私交付）

1. **Demo 登录系统**（依据《Heartbell-v2.5-Demo登录交付》）：新增 `/login` 登录页与预置演示账号；同浏览器双 Cookie 槽位（`hb_demo_a` / `hb_demo_b` / `hb_demo_c`）支持 A/B 双窗口并行登录；全部用户接口（`/api/v2` 普通用户路由与旧 `/api/demo`）在执行任何业务前先校验服务器会话——viewer 参数只选择槽位，不再作为身份证明；「我的」显示登录账号并支持退出登录；会话 401 时停止轮询并回登录页。`APP_MODE=live` 拒绝 Demo 登录与会话。
2. **安全与隐私模块**（依据《Heartbell-v2.2-安全与隐私模块交付》M0–M3 完整本地集成）：
   - **集中隐私策略**（`privacy-policy.ts`）：授权读取 = 有效授权 + 未关闭连接 + 未被屏蔽；关闭连接/结束绑定/屏蔽/注销统一级联撤权；日记详情按版本裁剪（私人草稿仅作者可见，屏蔽后仅共同确认归档可读）；通知与雷达候选同样按策略过滤。
   - **屏蔽与解除**：服务端签发 `targetRef`（绑定调用者与来源，举报前不揭晓匿名身份）；屏蔽即双向停止发现/摇铃/邀请/授权并关闭连接、撤双向授权、取消待响应铃声与邀请——**不自动结束关系、不自动扣分**；解除屏蔽不恢复旧连接与授权。
   - **举报与运营工作台**：六种原因、10–1000 字说明、可选同时屏蔽（默认不勾选）；进度/补充/一次复核（7 天窗口、原审核员回避）；`/admin` 新增「安全工单」模块（脱敏队列、领取、补正、结案、复核、限时发现/摇铃限制）；举报不影响履约分。
   - **我的数据**：本人数据导出（范围可选、24 小时有效、不含存证 salt/他人草稿/后台意见）；注销账号（密码再认证 + 输入“注销” + 明确同意结束绑定；立即撤会话/撤权/停止发现；在途争议与必要材料诚实标注受限保留，独立受限凭据查询结果）。
   - 新增演示第三人 **c**（安全验证专用，始终无权读取 A/B 授权内容）。

## 启动

需要 Node.js 20.9+ 及 npm。

```bash
npm ci
npm run dev
```

打开 http://localhost:3000/login ，使用预置 Demo 账号登录后进入对应窗口（约 420px 宽）：

| 演示角色 | username | password | userId | 说明 |
|---|---|---|---|---|
| Demo A | `a` | `HeartbellA2026!` | a | 小铃（双人演示主窗口） |
| Demo B | `b` | `HeartbellB2026!` | b | 阿响（双人演示第二窗口） |
| Demo C | `c` | `HeartbellC2026!` | c | 小柯（v2.6 安全验证第三人） |

凭据为公开演示凭据，仅 `APP_MODE=demo` 可用；同浏览器可同时登录多个账号（各自独立 Cookie 槽位，互不覆盖）；重启服务后需重新登录。主流程：

1. **相遇**：双方勾选成年声明 → 选临时特征 → 开启 10 分钟雷达 → 一方摇铃 → 对方回响（来铃可"稍后决定"，保留在「相遇」的待决定列表随时重新处理）→ 双方档案揭晓（回响前服务端不返回档案）。
2. **了解**：查看对方交往意向与应用内状态；对方在「我的」中授权后可见**关系履约参考**（演示人物 B 预置 71 分虚构前史，A 无历史显示"暂无足够记录"）；联系方式独立双向授权；双方确认建立关系（已有关系时服务端拦截雷达与摇铃）。
3. **我们**：共同封面、在一起天数、时间线；日记（标题 40 字/正文 3000 字/6 张演示图）私人草稿→发送→双方确认→可存证；修改生成新版本并重新确认；重要承诺（计分项限额、履约记录、豁免与申诉）；任一方可单方结束绑定。
4. **相守**（恋爱保险概念演示 · 演示点数）：双方各投 100 点 → 24h 冷静期 → 365 天有效期 → 达成申请核验 → 演示台审核 → 7 天争议期 → 领取点数奖励或 99 朵玫瑰演示券；普通结束进入 7 天异议窗口后失效（投入进入不可流通的演示失效账户）；例外复核独立处理；退出关系不等待结算。

演示台 http://localhost:3000/demo/admin （仅 APP_MODE=demo）：场景重置、虚拟业务时间推进、审核模拟（通过/补材料/不通过）、例外复核结论、链故障模拟。

## 已实现与限制

- 四栏导航 + 头像进入「我的」；`?tab=meet|know|us|future` 保存位置；360/390/430px 无横向溢出（已实测）。
- 履约分与相守点数是两套独立数据：分数不可充值/消费/兑换，点数投入/领取不影响分数。
- 所有业务权限与状态迁移在服务端校验；v2.6 起用户接口需先通过 Demo 会话（双 Cookie 槽位），`admin/*` 演示台与 `/api/v2/ops` 管理接口保持各自独立的会话体系。
- 内存存储，重启清空（P0 明确标注的本地演示）；刷新可恢复本次服务状态；登录会话表同样为单进程内存（重启后重新登录）。
- 上链：默认 preview 模式只保留本地承诺指纹，**不生成假交易哈希/假区块/伪浏览器链接**；真实链需配置 `CHAIN_MODE` + RPC + 合约地址 + writer 密钥（见 docs/WEB3.md，本轮未部署、未发送真实交易）。
- 钱包连接保留（我的抽屉内），仅用于真实存证签名；ZK 验证器未配置时拒绝验证。
- 模拟标识始终可见：位置、演示前史、审核台结论、玫瑰券（不可实际核销）。
